一句话策略逻辑

先用事件发现找到可能有厚度的币，再用跨所或现货-永续结构降低方向暴露；候选必须经过 BBO 新鲜度、订单簿扫单价、费用、资金费率 interval、交易所可用性和审计字段校验，最后才允许小额 live。

01

事件发现

涨跌幅榜、volume zscore、funding per hour、perp premium、跨所 dispersion、控盘/叙事币。

02

信号归并

raw 行写入 watch_signal_raw，连续触发合并成 watch_signal_event。

03

结构表达

Type B: 低价所 long perp + 高价所 short perp；Type C: long spot + short perp。

04

可成交验证

不用 last/mark 直接判断；按目标名义金额 sweep 订单簿，检查深度、滑点、方向。

05

模型排序

V1 5 因子和 V2 Ridge/Logistic 输出 pnl_hat、win_prob。

06

实盘审计

信号、订单、费用、资金费、拒绝原因、余额快照和平仓原因全部落库。

行情与数据底座

Flask 主服务 simple_app.py 运行在 4002，采集多交易所 WebSocket/REST 行情；SQLite 保存历史价格，本地 PostgreSQL 保存 watchlist raw/event 和 live trading 审计。

核心文件：config.py、exchange_connectors.py、database.py、watchlist_pg_writer.py

Watchlist 与事件池

watchlist_manager.py 生成 Type A/B/C 信号，并把 Type B/C 推送到 PG event、模型预测、订单簿复核和 live trading kick 链路。

入口：Watchlist、Watchlist 图表、DB 浏览

订单簿与门控

事件首次写入时按候选交易所抓订单簿，枚举 pair 与方向，选出真正可成交的 long/short 组合；实盘侧再次复验，失败则记录 no_tradable_direction、below_threshold 等原因。

实盘执行与风控

live_trading_manager.py 负责候选读取、开仓、监控、止盈、超时平仓和余额快照；trade_executor.py 封装 Binance/OKX/Bybit/Bitget 等后端。

当前旧参数：最多 10 组对冲，每腿 50U。

研究结果摘要

研究线结果展示口径
Event-first 主线项目已从全市场薄因子转向“事件发现 → 可成交验证 → 结构化交易 → 审计”。目标是在控盘/榜单/拥挤事件中找更厚的 funding/basis 机会。这是当前策略总框架，详见 Strategy Decision。
IC/IR 因子raw_slope_3m、raw_drift_ratio、raw_crossings_1h、spread_log_short_over_long 等在多个 horizon 有排序价值。作为事件后的排序/过滤器，不单独作为实盘充分条件。
V2 Ridge + Logistic约 15k 个 B/C 样本；valid AUC: 60m 0.7165、240m 0.7228、480m 0.7240、1440m 0.7255。说明模型有排序价值，但 valid window 只有 7 天，必须进入 paper/live 审计。详见 V2 summary。
5 因子 PnL 模型Top 分位真实 mean pnl 与 win rate 更高；但 fee/slippage 仍是关键约束。用于候选排序和阈值辅助，详见 5 factor report。

多因子模型如何落地

v1：5 因子线性回归

v1 针对 Type B/C 读取事件后的 5 个基础因子，直接输出 pnl_hat 和近似 win_prob。它的价值是给候选做轻量排序，而不是替代盘口验证。

  • 因子：raw_slope_3m、raw_drift_ratio、spread_log_short_over_long、raw_crossings_1h、raw_best_buy_high_sell_low
  • 使用口径：先过事件和订单簿门控，再按 pnl_hat 排序；win_prob 只代表 P(pnl > fee_threshold) 的近似。

v2：序列因子 + Ridge / Logistic

v2 读取更完整的价差、资金费和质量特征，分别对 240m / 1440m 做收益和胜率建模。它能提供更细的排序信息，但仍然不直接决定是否下单。

  • 输入：spread 序列、funding edge、zscore、crossings、vol ratio、缺失率质量标签等。
  • 使用口径：仅当 missing rate、订单簿方向和资金费门控都通过时，才把 v2 分数纳入 live 候选。

关键字段说明

表/字段含义读数方式
watch_signal_raw.triggered分钟级候选是否触发 watchlist 条件。用于生成事件池，不等于可下单。
watch_signal_event.features_agg事件聚合特征，包含因子、预测、订单簿验证、trigger details。实盘从这里读取候选质量和腿信息。
